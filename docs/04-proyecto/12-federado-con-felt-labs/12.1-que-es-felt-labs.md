# 12.1 Qué es FELT Labs

> **Qué responde:** ¿qué construyeron exactamente, y cómo encaja con Ocean?

## El resumen en una frase

FELT Labs es una plataforma de aprendizaje federado construida **encima** de
Ocean Protocol: Ocean se encarga de los datos, los permisos y los pagos; FELT
pone los algoritmos de entrenamiento y agregación, y una aplicación web que
orquesta los jobs.

La división de responsabilidades es la que ya viste en → 11.0:

| Capa | Quién |
|---|---|
| Gobernanza, catálogo, permisos, pagos | **Ocean Protocol** (+ Polygon) |
| Ejecución aislada junto a los datos | **Compute-to-Data** |
| Algoritmos de federado y protocolo de privacidad | **FELT** |
| Orquestación y experiencia de usuario | **App de FELT** |

---

## Dos algoritmos, un contenedor

Esta es la decisión de diseño que hay que entender antes que ninguna otra.

FELT publica en Ocean **dos assets de algoritmo**, no uno:

| Algoritmo | Qué hace | Dónde corre |
|---|---|---|
| **Entrenamiento local** | Entrena sobre el dataset del proveedor y devuelve el modelo cegado y cifrado | En el nodo de **cada** proveedor de datos |
| **Agregación** | Descifra los modelos locales y los promedia | En **otro** job C2D |

Y lo curioso: **los dos usan la misma imagen Docker**. Lo único que cambia es el
comando de arranque. Un contenedor Python con la librería `feltlabs` instalada,
y dos entrypoints distintos.

```none
                  imagen: feltlabs/feltlabs-py
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
   python -m feltlabs train      python -m feltlabs aggregate
   (K jobs, uno por dataset)     (1 job, sobre las K salidas)
```

Nuestra reimplementación mantiene el patrón: `docker/Dockerfile` no define
`ENTRYPOINT`, y `algorithms/` contiene los dos scripts.

## El flujo completo

```none
  APP DE FELT              PROVEEDOR A      PROVEEDOR B      NODO AGREGADOR
 ─────────────            ─────────────    ─────────────    ────────────────
 1. eliges datasets
    y tipo de modelo
         │
         ├── job C2D ────▶ 2. entrena
         │                    cega + cifra
         │                 3. devuelve ─────────────────┐
         │                                              │
         ├── job C2D ─────────────────▶ 2'. entrena     │
         │                                  cega+cifra   │
         │                              3'. devuelve ────┤
         │                                              │
         └── job C2D ──────────────────────────────────▶ 4. descifra
                                                           promedia
                                                        5. devuelve
         ◄─────────────────────────────────────────────────┘
 6. descargas el global
    y le quitas el ruido
```

**Cuenta de jobs:** con K proveedores, una ronda cuesta **K + 1 jobs C2D**. Ese
+1 es el precio del doble ciego, y es la diferencia estructural con la sección 11
(→ [12.6](12.6-felt-frente-a-la-seccion-11.md)).

## El contrato con el contenedor

Idéntico al de → 11.6, porque es el de Ocean y no el de FELT:

```none
/data/inputs/<DID>/<ficheros>       un subdirectorio por dataset
/data/inputs/algoCustomData.json    parámetros del job, JSON libre
/data/outputs/model                 ÚNICA salida, nombre fijo
```

Tres detalles que cuestan tiempo si no los sabes:

1. **El nombre del fichero de salida es `model`.** No es convención: el
   siguiente eslabón lo busca por ese nombre exacto.
2. **Cada dataset llega en su propia carpeta**, nombrada con el DID. Un job
   puede recibir varios.
3. **`algoCustomData.json` es el único canal de parámetros.** En FELT viajan por
   ahí el tipo de modelo, la semilla y —en el job de agregación— las URLs de los
   modelos locales.

En el laboratorio esto vive en `src/feltc2d/ocean.py`, y hay tests de contrato
que lo fijan:


## Los modelos que soporta

FELT no entrena cualquier cosa. Su librería envuelve tres familias:

| Familia | Qué incluye |
|---|---|
| **scikit-learn** | Modelos lineales, y en general lo que tenga pesos promediables |
| **Analítica** | Estadísticos simples (media, varianza, conteos) sobre datos distribuidos |
| **TensorFlow** | Redes, incluida una CNN de ejemplo |

La restricción real no es el framework: es que **el modelo debe poder
promediarse coordenada a coordenada**. Cualquier modelo cuyos parámetros no
tengan una correspondencia uno a uno entre nodos —árboles, k-NN, modelos con
tamaño variable— queda fuera de FedAvg, y por tanto de FELT.

Nuestra reimplementación usa NumPy puro a propósito (→ [12.3](12.3-lab0-el-protocolo-en-memoria.md)).

## Lo que FELT añade sobre Ocean, en concreto

Vale la pena listarlo porque es exactamente lo que tendrías que construir tú:

- [x] Un contenedor con los dos algoritmos, publicado y listo para usar.
- [x] El protocolo de cegado y cifrado (→ [12.2](12.2-el-protocolo-de-doble-ciego.md)).
- [x] Una aplicación que orquesta K+1 jobs y encadena sus salidas.
- [x] Gestión de claves: genera el par del agregador y lo asocia al job.
- [x] Firmado automático de transacciones, para no aprobar K+1 veces en la wallet.
- [x] Un flujo alternativo en Python para automatizar sin navegador.

Es bastante trabajo. Que exista y funcione es información valiosa aunque acabes
no usándolo.
