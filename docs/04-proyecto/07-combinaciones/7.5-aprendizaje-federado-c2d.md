# 7.5 Aprendizaje Federado sobre Ocean Protocol C2D

> Laboratorio incremental para entender y ejecutar un pipeline de **aprendizaje
> federado** sobre la infraestructura **Compute-to-Data** de **ocean-node**.
> Cuatro escalones. En cada uno cambia **una sola variable**.

---

## Por qué cuatro labs y no un tutorial

Un pipeline federado sobre C2D junta cuatro tecnologías a la vez: aprendizaje
federado, Docker, la API de un nodo Ocean y criptografía de firmas. Si lo montas
todo de golpe y falla, no sabes cuál de las cuatro capas falló.

Aquí cada lab añade **exactamente una**:

| Lab | Añade | Quita como sospechoso | Tiempo |
|-----|-------|----------------------|--------|
| **0** | Aprendizaje federado | — | 2 min |
| **1** | El patrón de ficheros | la lógica federada | 5 min |
| **2** | Docker | el contrato de ficheros | 15 min |
| **3** | `ocean-node` | la imagen | tu servidor |

El código de entrenamiento es **el mismo en los cuatro**. Solo cambia el
adaptador de almacenamiento. Cuando el Lab 3 falle (fallará), ya sabrás que el
problema es de infraestructura.

## Los tres ejemplos

Complejidad creciente, todos con datos sintéticos generados con NumPy. Sin
descargas, sin scikit-learn, sin PyTorch.

### 01 - Regresión lineal: `y = 3x + 2`

Dos parámetros. Tres nodos que ven **tramos disjuntos del eje X**: ninguno puede
estimar bien la recta en solitario. Puedes leer la convergencia a ojo.

```none
 ronda         w         b   mse medio
     1    2.4715    0.4186      1.5575
    10    3.0006    1.7918      0.2482
    40    3.0004    1.9770      0.2406
```

### 02 - El efecto no-IID y la deriva de clientes

Giramos la perilla `alpha` (reparto Dirichlet) y medimos dos cosas:

| alpha | % clase 1 por nodo | accuracy | divergencia |
|-------|--------------------|----------|-------------|
| 100.0 | 0.48 0.48 0.51 0.50 | 0.7333 | **0.309** |
| 1.0 | 0.22 0.45 0.78 0.53 | 0.7300 | **1.755** |
| 0.3 | 0.44 1.00 0.94 0.23 | 0.7367 | **2.696** |

**La accuracy no se mueve. La divergencia se multiplica por 9.**

Ese resultado sorprende y es la mejor lección del laboratorio. La regresión
logística es convexa: promediar soluciones locales sigue cayendo cerca del único
mínimo. Una red profunda no tiene esa garantía. Si tu prueba de concepto usa un
modelo lineal y funciona, **todavía no has probado nada** sobre la red que
quieres desplegar. La divergencia es la señal temprana que sí se traslada.

### 03 - Tres hospitales: la tabla que justifica el data space

| Escenario | Accuracy |
|-----------|----------|
| Centralizado (techo, ilegal en la práctica) | 0.9217 |
| **Federado - FedAvg ponderado** | **0.9217** |
| Federado - media simple (bug) | 0.9167 |
| Solo local - Hospital A (n=110) | 0.9113 |
| Solo local - Hospital B (n=60) | 0.8613 |
| Solo local - Hospital C (n=30) | **0.6470** |

El hospital pequeño pasa de **0.647 a 0.922**: +27,5 puntos sin mover un solo
dato. Y el federado **alcanza el techo centralizado**.

Esta es la tabla que va en la presentación. Si el federado no supera claramente
al "solo local", no hay ningún motivo para montar toda esta infraestructura.

## Estructura

```none
labs/flower-ocean-c2d/
├── src/fedlab/
│   ├── ports.py                 # los 3 contratos (Protocol). Todo depende de esto
│   ├── config.py                # TrainConfig inmutable
│   ├── serialization.py         # JSON y NPZ. SIN PICKLE
│   ├── domain/                  # ← cero I/O, cero Ocean, cero Docker
│   │   ├── aggregation.py       #   FedAvg ponderado (funciones puras)
│   │   ├── round.py             #   el caso de uso: UNA ronda local (15 lineas)
│   │   └── datasets.py          #   generadores sinteticos + particion Dirichlet
│   ├── learners/                # linear.py, logistic.py (NumPy puro)
│   ├── adapters/                # ← aqui vive TODO el I/O
│   │   ├── stores.py            #   InMemory | File | C2D
│   │   └── sources.py           #   Csv | Synthetic | Array
│   ├── entrypoints/
│   │   ├── client_main.py       # ← el UNICO fichero que sabe de C2D
│   │   └── simulate.py          #   bucle federado en memoria
│   └── ocean/                   # cliente HTTP + orquestador
├── examples/                    # ex01, ex02, ex03
├── scripts/                     # make_datasets, run_lab1, run_lab3
├── tests/                       # 38 tests, < 2 s
└── docker/Dockerfile
```

**La regla que lo ordena todo:** las dependencias apuntan hacia dentro.
`domain/` no importa `os`, ni `requests`, ni nada de Ocean. Ocean es un detalle
de infraestructura, no el centro del diseño.
