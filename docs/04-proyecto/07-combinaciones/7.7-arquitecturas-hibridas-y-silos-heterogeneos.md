# 7.7 Arquitecturas Híbridas y Silos Heterogéneos en Data Spaces

> **Qué responde:** ¿Tiene sentido combinar Redes Neuronales con Gradient Boosting (XGBoost/LightGBM)? ¿Cómo se gestionan datos tabulares procedentes de silos empresariales independientes con esquemas y columnas totalmente dispares en un Espacio de Datos?

---

## 🧩 La complementariedad de dos mundos

En el diseño de sistemas de aprendizaje automático existe una complementariedad fundamental entre dos familias de algoritmos debido a sus **sesgos inductivos (*inductive biases*) opuestos**:

* **Redes Neuronales (Deep Learning):** Extraen significado y relaciones no lineales suaves sobre datos continuos y no estructurados (**texto, imágenes, audio, grafos y secuencias temporales**).
* **Modelos de Árboles (GBDT - XGBoost / LightGBM / CatBoost):** Son los líderes indiscutibles en **datos tabulares heterogéneos** (variables categóricas de alta cardinalidad, datos no normalizados, divisiones ortogonales hiperplanas y robustez extrema frente a *outliers* y valores nulos).

```none
┌──────────────────────────────────────┐       ┌──────────────────────────────────────┐
│       REDES NEURONALES (DL)          │       │       GRADIENT BOOSTING (GBDT)       │
├──────────────────────────────────────┤       ├──────────────────────────────────────┤
│ • Datos no estructurados (Texto/Img) │       │ • Datos tabulares heterogéneos (CSV) │
│ • Fronteras de decisión suaves       │  ➕   │ • Fronteras de decisión escalonadas  │
│ • Optimización basada en gradientes  │       │ • Inmune a escalas y outliers        │
│ • Aprende representaciones latentes  │       │ • Máxima precisión con pocos datos   │
└──────────────────────────────────────┘       └──────────────────────────────────────┘
```

---

## 🏗️ Los 4 Patrones Reales de Arquitectura Híbrida

En la industria y en entornos de investigación competitivos, la combinación de ambas tecnologías se implementa siguiendo 4 patrones principales:

### Patrón 1: Red Neuronal como Extractor de Embeddings $\rightarrow$ GBDT
*Es el patrón rey en comercio electrónico y sistemas de recomendación a gran escala (Pinterest, Meta, Amazon).*

```none
[ Imagen / Foto ]    ──► [ Visión (ResNet / ViT) ]  ──┐
                                                      ├──► [ Concatenación ] ──► [ XGBoost / LightGBM ] ──► Decisión Final
[ Texto / Consulta ] ──► [ NLP (Mini-LLM / BERT) ] ───┤          ▲
                                                      │          │
[ Datos Tabulares ]  ─────────────────────────────────┴──────────┘
  (Precio, stock, edad del cliente, compras previas)
```

1. Las redes neuronales procesan el texto y las imágenes, comprimiéndolos en vectores densos (*embeddings* de 32 a 128 dimensiones).
2. Esos embeddings se concatenan junto a las columnas tabulares numéricas y categóricas tradicionales.
3. Un modelo **LightGBM o XGBoost** recibe la tabla enriquecida y toma la decisión final (probabilidad de clic, riesgo de fraude, estimación de precio).

---

### Patrón 2: Ensamble y *Stacking / Blending* en Paralelo
*Se aprovecha que los errores de los árboles y los de las redes están descorrelacionados.*

```none
                         ┌──► [ Red Neuronal Tabular (MLP) ] ──► Predicción A ──┐
                         │                                                      ├─► Meta-Modelo / Promedio ──► Salida
[ Mismo Dataset Tabular ]┤                                                      │   (Logit Blending)
                         └──► [ LightGBM / CatBoost ]        ──► Predicción B ──┘
```

* **Principio:** Si un MLP acierta el $88\%$ y un CatBoost el $89\%$, el ensamble de ambos suele alcanzar el **$91\%$** porque fallan en subconjuntos de datos completamente distintos.

---

### Patrón 3: GBDT para Generar Variables Categóricas $\rightarrow$ Red Neuronal
*El diseño clásico de Meta / Facebook para la predicción de clics en anuncios (He et al., 2014).*

1. Los datos tabulares se pasan a través de un bosque de árboles de decisión (GBDT).
2. Se extrae el **índice de hoja (*leaf index*)** en el que aterriza cada muestra dentro de cada árbol.
3. Estos índices se tratan como tokens categóricos que alimentan capas de *Embedding* de una red neuronal profunda que realiza la predicción final.

---

### Patrón 4: Redes Neuronales Diferenciables inspiradas en Árboles (*End-to-End*)
*Modelos de Deep Learning diseñados específicamente para imitar la lógica de división de árboles.*

* **TabNet (Google Cloud AI, Arik & Pfister 2020):** Utiliza atención secuencial dispersa (*sparsemax*) para seleccionar variables relevantes en cada paso de decisión de forma interpretable y totalmente derivable con `loss.backward()`.
* **NODE (*Neural Oblivious Decision Ensembles*):** Ensambles de árboles continuos optimizables punto a punto mediante gradiente descendente en PyTorch.

---

## 🏢 El Reto en Espacios de Datos: Silos Tabulares Heterogéneos

En un **Espacio de Datos Soberano (Data Space bajo IDSA / Gaia-X / Ocean Protocol)**, surge un problema estructural:

1. **Cada empresa tiene su propio esquema:** La Empresa A tiene `[edad, salario_anual]`, la Empresa B tiene `[age, monthly_income, credit_score]` y la Empresa C tiene `[experiencia, sector, retribucion]`.
2. **Soberanía y RGPD:** No es legal ni viable enviar los datos crudos a un servidor central para unificar tablas.

> ⚠️ **Por qué fallan los árboles clásicos:** Un XGBoost estándar exige una **matriz homogénea rígida $N \times D$** donde todas las columnas existan exactamente en todas las filas. No puede operar de forma nativa sobre esquemas dispares sin forzar una sincronización previa.

---

### 🛡️ Los 4 Enfoques para Silos Heterogéneos en Data Spaces

```none
┌──────────────────────────────────────────────────────────────────────────────────┐
│ ENFOQUE A: Encoders Locales Privados -> Espacio Latente Común                    │
│   • Empresa A (4 cols) -> [ Encoder Local A ] ──┐                                │
│                                                 ├──► [ Vector Latente 32-dim ]  │
│   • Empresa B (7 cols) -> [ Encoder Local B ] ──┘    (Espacio semántico unificado│
├──────────────────────────────────────────────────────────────────────────────────┤
│ ENFOQUE B: Serialización a Texto + Tabular Foundation Models                     │
│   • Fila A: "edad: 42 | salario: 50000"                                         │
│   • Fila B: "age: 42 | annual_income: 50k | score: 720"                          │
│   • Un Transformer / Mini-LLM procesa el significado sin importar las columnas.  │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ENFOQUE C: Aprendizaje Federado Vertical (VFL / Split Learning)                  │
│   • Mismos usuarios compartidos entre empresas, pero con atributos diferentes.   │
│   • Banco A (historial) + Aseguradora B (salud) unen vectores intermedios.       │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ENFOQUE D: Mapeo Ontológico Semántico (Data Spaces IDSA / Gaia-X)                │
│   • Transformación en el conector local hacia un vocabulario de datos común.    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

#### 1. Encoders Locales Privados $\rightarrow$ Espacio Latente Común *(El estándar federado)*
* Cada empresa entrena una pequeña red neuronal local (un Autoencoder o proyector MLP) que traduce sus columnas particulares a un **vector de embedding universal** de dimensión fija (ej. 32 dimensiones).
* El modelo global federado solo recibe y procesa estos vectores de 32 dimensiones.
* **Garantía de privacidad:** Ninguna empresa revela el nombre ni el número de sus columnas internas; solo comparte representaciones numéricas abstractas.

#### 2. Serialización Semántica con Modelos Tabulares Fundacionales (*Tabular LLMs*)
* En lugar de una matriz numérica fija, cada fila se serializa como texto estructurado (ej. `"edad: 35 | puesto: analista | sueldo: 40000"`).
* Modelos como **TabPFN** o Transformers tabulares procesan la semántica de las variables mediante atención (*Self-Attention*), entendiendo que `"sueldo"` y `"annual_income"` representan conceptos análogos aunque el esquema difiera.

#### 3. Aprendizaje Federado Vertical (*Vertical Federated Learning / Split Learning*)
* Se aplica cuando varias empresas comparten los **mismos sujetos** (ej. los mismos clientes), pero cada entidad posee atributos completamente distintos.
* Las redes locales computan activaciones intermedias (*embeddings*) y se sincronizan mediante intercambio seguro de gradientes sin exponer las tablas de origen.

#### 4. Mapeo Semántico en el Conector del Data Space
* A nivel de infraestructura (Conectores EDC / Ocean Nodes), se implementa un pipeline de ingesta que mapea las propiedades locales hacia una **ontología común del espacio de datos** antes de alimentar los algoritmos de entrenamiento.

---

## 📊 Matriz de Decisión para Proyectos Reales

| Escenario | Estrategia Recomendada | Algoritmos / Herramientas |
|---|---|---|
| **Tabla única centralizada homogénea (< 500k filas)** | GBDT puro | LightGBM, CatBoost, XGBoost |
| **Tabla centralizada multimodal (Tablas + Fotos + Textos)** | Extractor DL + GBDT | PyTorch (ViT/BERT) + LightGBM |
| **Silos federados con las mismas columnas (Horizontal)** | Federado Clásico | Flower + PyTorch / SecureBoost |
| **Silos federados con esquemas y columnas dispares** | Encoders Locales a Espacio Latente | Autoencoders locales + Modelo Federado |
| **Silos con mismos clientes pero datos complementarios** | Federado Vertical / Split Learning | Split Neural Networks / Fate / PySyft |
