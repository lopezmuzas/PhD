# 15.4 Lab 2 — El router propio

> **Estado: esbozo.** Depende del [Lab 1](15.3-lab1-el-proxy-espia.md): sin
> registros no hay política que evaluar. La tabla de umbrales es un punto de
> partida arbitrario, pensado para ser corregido con datos.

## La pregunta

¿Cuánto se ahorra decidiendo a mano qué va a cada modelo, y cuánto se pierde
en calidad al hacerlo?

La recomendación estándar es escalar de barato a caro. Pero dicha así es un
consejo, no una política: no dice dónde está el umbral ni cómo se mide el
acierto. Escribirla explícitamente la vuelve medible.

## La política inicial

Sobre el mismo proxy, antes de reenviar, se sustituye el modelo pedido por el
elegido. Reglas heurísticas, deliberadamente simples:

```python
def elegir_modelo(cuerpo: dict, forzar_gratis: bool = False) -> str:
    mensajes = cuerpo.get("messages", [])
    texto = " ".join(str(m.get("content", "")) for m in mensajes).lower()
    n_chars = len(texto)

    if forzar_gratis:
        return GRATIS
    if cuerpo.get("tools"):                       # modo agente: necesita cabeza
        return CARO
    if any(p in texto for p in PALABRAS_DIFICILES):
        return CARO
    if n_chars > 20_000:                          # contexto grande, barato con 1M
        return MEDIO
    if n_chars < 800 and len(mensajes) <= 2:      # pregunta corta y suelta
        return BARATO
    return MEDIO
```

| Regla | Destino | Razón |
|---|---|---|
| Lleva `tools` | 5/5 | El modo agente encadena decisiones; un fallo se propaga |
| Palabras «difíciles» | 5/5 | Refactor, arquitectura, depuración, demostración |
| > 20.000 caracteres | 4/5 | DeepSeek V4 Pro tiene 1M de contexto a 0,44 $/M |
| < 800 caracteres y ≤ 2 mensajes | 3/5 | Pregunta suelta, no necesita frontera |
| Resto | 4/5 | Por defecto, el mejor coste/calidad |

Las palabras difíciles son un clasificador de bolsa de palabras, y es una
elección consciente: **empezar por lo más tonto que pueda funcionar**, medir su
tasa de error y solo entonces justificar algo mejor. Si nunca se equivoca, no
hacía falta nada más.

## Cómo se mide

Cada petición deja dos registros: la ruta elegida y el uso de tokens devuelto
por la API. Con una tabla de precios sale el coste real, y con ella también el
**contrafactual**: qué habría costado mandarlo todo al 5/5.

```
ahorro = coste_contrafactual / coste_real
```

Ese cociente es el número que va al cuaderno. Pero solo, no dice nada: hay que
acompañarlo de la tasa de peticiones mal enrutadas, que es la que **no** se
automatiza. Cada vez que una respuesta salga floja hay que anotar a qué modelo
fue y por qué regla llegó ahí.

| Métrica | Cómo se obtiene |
|---|---|
| Coste real | Suma del uso × precio por modelo |
| Coste contrafactual | Los mismos tokens al precio del 5/5 |
| Reparto de rutas | Recuento por modelo elegido |
| Errores de ruta | **A mano**, marcando las respuestas insuficientes |

Un ahorro de 10× con un 30 % de respuestas que hay que repetir no es un ahorro.

## Dónde se enchufa

En `main.py`, justo antes de reenviar:

```python
from app.router import elegir_modelo

pedido = cuerpo.get("model")
elegido = elegir_modelo(cuerpo)
cuerpo["model"] = elegido
registrar({"id": rid, "direccion": "ruta",
           "pedido": pedido, "elegido": elegido})
```

Registrar **pedido** y **elegido** por separado permite reconstruir después qué
habría pasado con otra política, sin volver a lanzar nada.

## La pregunta abierta

Esto es una política escrita a mano. La versión interesante es aprenderla:
estado = características de la petición (longitud, tipo, ficheros adjuntos,
presencia de herramientas), acción = modelo elegido, recompensa = calidad menos
coste.

Es un **bandido contextual**, y con registros acumulados de sesiones pasadas se
convierte en aprendizaje por refuerzo offline: aprender de decisiones ya tomadas
sin poder experimentar con las nuevas. Aparecen de golpe los problemas
conocidos: el sesgo del registro (solo se ve la recompensa de la acción elegida)
y la necesidad de validar fuera de la distribución observada.

porque es el punto donde esta sección de herramientas roza el tema de tesis en
vez de solo servirlo.
