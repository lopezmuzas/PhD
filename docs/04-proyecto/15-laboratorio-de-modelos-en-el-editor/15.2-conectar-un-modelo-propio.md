# 15.2 Conectar un modelo propio (protocolo OpenAI)

> Los dos endpoints de esta página están probados: `/v1/models` responde, el modo
> sin streaming devuelve el JSON correcto y el streaming emite chunks SSE
> cerrando con `[DONE]`.

## La idea

Continue habla el protocolo de OpenAI. **Cualquier cosa que exponga
`/v1/chat/completions` le vale**, incluido algo escrito a mano en sesenta líneas.
Eso convierte al editor en un cliente genérico y abre las tres páginas
siguientes: si puedo ponerme en medio, puedo espiar, medir y decidir.

| Vía | Cuándo | Provider |
|---|---|---|
| Shim propio en FastAPI | Modelo entrenado por mí, proxy o router | `openai` + `apiBase` |
| vLLM | Pesos de HuggingFace en GPU | `openai` + `apiBase` |
| Ollama | Un GGUF cuantizado | `ollama` |

## Los dos endpoints mínimos

`GET /v1/models` devuelve el catálogo. `POST /v1/chat/completions` genera, y
**tiene que soportar streaming**, porque es lo que el editor usa por defecto.
El formato de streaming es SSE: líneas `data: {json}` separadas por dos saltos
de línea, cerrando con `data: [DONE]`.

El código completo está en `labs/llm-lab/mi-modelo/mi_modelo_server.py`.
La parte que importa es dónde se enchufa el modelo:

```python
def generar(mensajes: list[dict], max_tokens: int = 512) -> str:
    """AQUÍ VA EL MODELO. Recibe [{"role":..., "content":...}], devuelve texto."""
    prefijo = mensajes[-1]["content"] if mensajes else ""
    return f"[eco] {prefijo}"
```

Y cómo se trocea la respuesta para el streaming:

```python
def stream_tokens():
    for palabra in texto.split(" "):
        yield _sse({"id": cid, "object": "chat.completion.chunk",
                    "created": creado, "model": MODEL_ID,
                    "choices": [{"index": 0,
                                 "delta": {"content": palabra + " "},
                                 "finish_reason": None}]})
    yield _sse({"id": cid, "object": "chat.completion.chunk",
                "created": creado, "model": MODEL_ID,
                "choices": [{"index": 0, "delta": {}, "finish_reason": "stop"}]})
    yield "data: [DONE]\n\n"
```

Se puede trocear por palabras, por caracteres o por tokens reales del modelo.
Para el [Lab 4](15.6-lab4-un-modelo-de-lenguaje-propio.md) lo interesante es
trocear por token, porque así se ve la generación al ritmo real del muestreo.

## Arrancar y conectar

```bash
cd labs/llm-lab/mi-modelo
uvicorn mi_modelo_server:app --host 127.0.0.1 --port 8000
```

```yaml
- name: "[?/5] Antonio · Modelo propio · LOCAL"
  provider: openai
  model: mi-modelo-v1
  apiBase: http://127.0.0.1:8000/v1
  apiKey: no-importa          # el cliente lo exige, mi servidor lo ignora
  roles: [chat]
```

El `apiKey` es obligatorio en el cliente aunque el servidor no lo mire. Poner
cualquier cosa.

## Las otras dos vías

**vLLM**, para pesos de HuggingFace en GPU. Expone la API de OpenAI de forma
nativa, sin shim:

```bash
vllm serve Qwen/Qwen2.5-Coder-7B-Instruct --port 8001
```

```yaml
- name: "[?/5] Antonio · vLLM local · LOCAL"
  provider: openai
  model: Qwen/Qwen2.5-Coder-7B-Instruct
  apiBase: http://127.0.0.1:8001/v1
  apiKey: no-importa
  roles: [chat, edit]
```

**Ollama**, para un GGUF cuantizado. Provider propio, sin `apiBase`:

```yaml
- name: "[?/5] Antonio · GGUF local · LOCAL"
  provider: ollama
  model: mi-modelo-cuantizado
  roles: [chat]
```

## Por qué esto importa más de lo que parece

El shim no es solo para servir modelos propios. Es la pieza que permite
**interponerse**: si el editor cree que habla con un modelo y en realidad habla
con código mío, puedo registrar el tráfico ([15.3](15.3-lab1-el-proxy-espia.md)),
redirigirlo a otro modelo ([15.4](15.4-lab2-el-router-propio.md)) o duplicarlo
contra varios a la vez ([15.5](15.5-lab3-el-banco-de-pruebas.md)).

Y es agnóstico del editor: habla el protocolo de OpenAI, así que sobrevive a
cambiar de herramienta.
