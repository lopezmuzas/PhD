# 15.3 Lab 1 — El proxy espía

> **Estado: esbozo.** El código está escrito y la sintaxis validada, pero no se
> ha ejecutado nunca contra tráfico real. Los números de la sección «qué buscar»
> son hipótesis, no medidas.

## La pregunta

¿Qué le manda realmente el editor al modelo?

Cuando escribo «arregla esta función», el modelo no recibe esas cuatro palabras.
Recibe un system prompt que no he escrito, el fichero abierto, quizá otros
ficheros del proyecto, las reglas del `.continue/`, el historial de la
conversación y una descripción de las herramientas disponibles. Nada de eso
aparece en la documentación con detalle suficiente.

La única forma de saberlo es mirar el cable.

## La idea

Ponerse **entre** el editor y OpenRouter. Reenviar todo tal cual, registrando de
paso la petición completa y la respuesta.

```
  VS Code ──▶ proxy (8080) ──▶ OpenRouter ──▶ modelo
                  │
                  ▼
            logs/*.jsonl
```

Es el mismo ejercicio que las Fases 0–5 del laboratorio, desplazado un nivel:
en vez de mirar dentro del modelo, mirar dentro del sistema que lo usa. Y es la
misma operación que interponerse en el tráfico de un contrato C2D (**→ 11**):
colocarse en el punto por donde pasa todo y anotar.

## Lo que hay que resolver

**El streaming.** Si el proxy espera a tener la respuesta entera para
registrarla, el editor pierde el efecto de escritura progresiva y parece
colgado. La solución es reenviar cada trozo según llega y **acumular en paralelo**
para registrar al final:

```python
async def reenviar():
    trozos = []
    async with cliente.stream("POST", f"{ORIGEN}/chat/completions",
                              json=cuerpo, headers=cabeceras) as r:
        async for linea in r.aiter_lines():
            if linea.startswith("data: ") and linea[6:] != "[DONE]":
                try:
                    d = json.loads(linea[6:])
                    c = d["choices"][0]["delta"].get("content")
                    if c:
                        trozos.append(c)
                except (json.JSONDecodeError, KeyError, IndexError):
                    pass
            yield linea + "\n\n"          # al editor, sin retenerlo
    registrar({"id": rid, "direccion": "respuesta",
               "ms": int((time.time() - t0) * 1000),
               "texto": "".join(trozos)})
```

**El formato de registro.** JSONL, una línea por evento, un fichero por día.
Se puede consultar con `jq` sin cargar nada en memoria y crece sin romperse.

**La clave.** La pone el proxy, no el editor. En el `config.yaml` se escribe
`apiKey: no-importa` y la clave real vive en el `.env` del proxy. Efecto
colateral útil: deja de haber claves repetidas treinta veces en la configuración.

El código completo está en `labs/llm-lab/proxy/app/main.py`.

## Montaje

Local, para empezar:

```bash
cd labs/llm-lab/proxy
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export OPENROUTER_API_KEY=sk-or-v1-...
uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
curl http://127.0.0.1:8080/salud
```

Con Docker, coherente con el resto de stacks (ver
[15.7](15.7-como-esta-montado.md)):

```bash
cd labs/llm-lab && cp .env.example .env   # y poner la clave
docker compose up -d proxy
```

Apuntar el editor al proxy:

```yaml
- name: "[4/5] DeepSeek · V4 Pro (via proxy espía) · PAGO barato"
  provider: openai
  model: deepseek/deepseek-v4-pro
  apiBase: http://127.0.0.1:8080/v1
  apiKey: no-importa
  roles: [chat, edit, apply]
```

## Qué buscar en los registros

```bash
# ¿cuánto contexto mete el editor en cada petición?
jq -r 'select(.direccion=="peticion") | "\(.n_mensajes) msgs  \(.caracteres) chars"' \
  logs/trafico-*.jsonl

# el system prompt oculto
jq -r 'select(.direccion=="peticion") | .mensajes[0].content' \
  logs/trafico-*.jsonl | head -50

# latencia mediana
jq -r 'select(.direccion=="respuesta") | .ms' logs/trafico-*.jsonl \
  | sort -n | awk '{a[NR]=$1} END{print "mediana:", a[int(NR/2)], "ms"}'
```

Preguntas concretas que responder y anotar en el cuaderno:

1. ¿Cuántos caracteres de contexto acompañan a una pregunta de diez palabras?
2. ¿Cambia el system prompt entre modo chat, modo edición y modo agente?
3. ¿Mete ficheros que no he abierto? ¿Con qué criterio los elige?
4. ¿Cuánto del contexto es realmente útil para la respuesta que devuelve?

La cuarta es la interesante, porque de ella sale directamente el ahorro posible
en el [Lab 2](15.4-lab2-el-router-propio.md): todo contexto inyectado y no usado
es dinero gastado en tokens de entrada.

## La conexión con C2D

No es una metáfora, es la misma estructura. Merece la pena desmontarla, porque
aclara qué papel se está ensayando aquí.

### Los dos son un límite de confianza donde solo se ve lo que cruza

C2D invierte el modelo tradicional: en vez de mandar los datos al algoritmo,
manda el algoritmo a los datos. Se crea un pod aislado, carga el algoritmo,
carga el dataset, ejecuta, y devuelve **los resultados y los logs**; después el
pod se borra a sí mismo junto con el dataset y el algoritmo.

Fíjate en lo que le queda al consumidor cuando termina. Resultados y logs. Nada
más. No puede inspeccionar los datos, ni el proceso, ni verificar por su cuenta
que se ejecutó lo que dice que se ejecutó. Su única ventana al cómputo es un
registro que le entrega otro.

Esa es exactamente la situación de quien usa un asistente en el editor: el
editor construye un prompt que no se ve, lo manda a un modelo que no se
controla, y devuelve texto. La diferencia es que aquí sí se puede uno
interponer.

### Dónde se rompe la analogía

La garantía de C2D **depende precisamente de que el consumidor no pueda
interponerse**. Si pudiera meter un proxy dentro del pod, el modelo entero se
cae. Este proxy funciona porque uno es dueño de los dos extremos.

Es decir: montarlo no enseña a auditar un C2D ajeno. Enseña a construir el lado
que registra —el papel del proveedor de datos, que es el que se ocupa al correr
un ocean-node (**→ 11**)—. Y ese lado tiene un problema de diseño idéntico: qué
registrar, con qué identificador correlacionar, y cómo no filtrar en el log lo
mismo que se está protegiendo.

### Los primitivos son los mismos

| En este proxy | En C2D |
|---|---|
| `rid`, un UUID por petición | Job ID / DID del activo |
| JSONL append-only, uno por día | Logs del job devueltos al consumidor |
| Petición y respuesta como eventos separados | Entrada (algoritmo, dataset) y salida (resultados) |
| El log contiene el código fuente enviado | El log puede filtrar información del dataset protegido |
| Reenvío en streaming sin retener | El pod devuelve resultados sin exponer el volumen |

La cuarta fila es la interesante: en C2D y en aprendizaje federado, **el canal de
salida es el canal de fuga**. Un log demasiado detallado sobre un dataset
privado es una brecha, igual que unos gradientes demasiado detallados lo son en
federado.

### El uso práctico inmediato

Cuando el lab de ocean-node del 11 se ejecute contra un nodo vivo, el mismo
patrón sirve: **mitmproxy en modo reverse proxy delante del nodo**, y aparecen
los payloads reales —los DDO, las peticiones firmadas, el sondeo de estado del
job, los códigos de error que la documentación no lista—. Es la técnica estándar
de depuración de integraciones, y ahorra semanas de adivinar.

### La pregunta que abre esto

Ocean plantea la procedencia verificable como respuesta a la regulación europea
de IA: no basta con saber qué datos alimentan un modelo, hay que demostrarlo.

El JSONL de este lab es una versión casera de eso, y como prueba no vale nada:
lo escribe uno mismo, se puede editar, y nada ata una línea a un hecho. La
pregunta —de tesis, no de herramientas— es **qué convierte un registro en
evidencia**. Ver [15.8](15.8-recursos-y-referencias.md#procedencia-la-pregunta-abierta).

## Riesgos

- **La clave viaja en el `.env`.** Nunca a git (ver `.gitignore` en 15.7).
- **Los registros contienen el código fuente completo** que se envía al modelo.
  Si en algún momento pasa por ahí material no publicado, el directorio de logs
  hereda esa sensibilidad.
- **Escuchar solo en `127.0.0.1`.** Un proxy con la clave dentro, expuesto a la
  red, es una factura ajena esperando a ocurrir.
