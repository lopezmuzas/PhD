# 11.5 Lab 3 · ocean-node

**Objetivo:** ejecutar el bucle federado contra tu nodo. Cambia **una** cosa:
quien arranca el contenedor.

> **Aviso.** El cliente HTTP de `src/fedlab/ocean/` esta construido leyendo el
> código fuente de ocean-node, pero **no se ha ejecutado contra un nodo vivo**.
> Los endpoints, el esquema de firma y los códigos de estado están verificados
> contra el fuente; el comportamiento en red, no. Empieza por el smoke test.

---

## Paso 1: smoke test (antes de nada)

No lances un bucle federado contra un nodo que no sabes si responde.

```bash
# 1. El nodo esta vivo?
curl http://tu-servidor:8000/api/services/computeEnvironments | python -m json.tool

# 2. Que devuelve el nonce?
curl "http://tu-servidor:8000/api/services/nonce?userAddress=0xTU_DIRECCION"
```

De la primera llamada necesitas el `id` de un entorno de computo. Anotalo.

```python
from fedlab.ocean.client import OceanNodeClient

c = OceanNodeClient("http://tu-servidor:8000", "0xTU_CLAVE")
print(c.address)
for env in c.environments():
    print(env["id"], env.get("resources"), env.get("free"))
```

Si esto falla, no sigas: el problema es de conectividad o de configuración del
nodo, no del laboratorio.

## Paso 2: un solo job, sin federación

```python
from fedlab.ocean.client import OceanNodeClient

c = OceanNodeClient("http://tu-servidor:8000", "0xTU_CLAVE")

job_id = c.start_free_job(
    environment=c.pick_free_environment(),
    image="tu-usuario/fedlab",
    tag="v1",
    checksum="sha256:...",                       # el digest del Lab 2
    entrypoint="python -m fedlab.entrypoints.client_main",
    dataset_url="https://tu-host/ex03_hospital_a.csv",
    custom_data={"config": {"epochs": 40, "lr": 0.4}},
    envs={"FL_MODEL": "logistic", "FL_FEATURES": "6"},
)
print(job_id)

c.wait(job_id)                                   # imprime cada cambio de estado
open("outputs.tar", "wb").write(c.result(job_id, index=0))
open("algo.log", "wb").write(c.result(job_id, index=1))   # index=1 = logs
```

**Descarga siempre el log (`index=1`)**, aunque el job vaya bien. Es donde vive
el `traceback` si algo revienta, y donde ocean-node deja `configuration.log` con
el detalle de que descargo y donde.

Si el job termina en 70 y el tar contiene `update.npz` y `metrics.json`, el
pipeline funciona. Lo demas es repetirlo.

## Paso 3: el bucle federado

## Que hace el orquestador en cada ronda

```python
custom = {"round": r, "config": cfg.to_dict()}
if global_params is not None:
    check_json_size(global_params)               # falla pronto si no cabe
    custom["params"] = params_to_json(global_params)

# un job por proveedor, en paralelo
with ThreadPoolExecutor(max_workers=len(providers)) as pool:
    results = list(pool.map(one, providers))

global_params = fedavg(updates)
```

Los jobs van en paralelo porque una ronda tarda lo que tarde el proveedor más
lento. En serie, con tres nodos, tardas el triple sin ganar nada.

`check_json_size` falla **antes** de lanzar los jobs si el modelo no cabe en
`algoCustomData`, con un mensaje que te dice la alternativa. Es mucho mejor que
descubrirlo con tres jobs a medias.

## Compute gratuito vs de pago

Este laboratorio usa `/api/services/freeCompute`: sin datatokens, sin gas, sin
escrow. Es lo correcto para aprender. Añadir la capa de contratos antes de que
el pipeline funcione solo mezcla dos fuentes de error.

Cuando pases a compute de pago cambia el endpoint, el comando de la firma y hace
falta `transferTxId` por cada asset. La lógica federada **no cambia**: sigue
siendo el mismo `run_federated` con otro cliente.

## Seguridad al desempaquetar

```python
tar.extractall(dest, filter="data")
```

Sin `filter="data"`, un tar con rutas `../../..` o absolutas escribe donde
quiera en tu máquina. Estas desempaquetando ficheros producidos por
**proveedores que no controlas**. El `filter` existe desde Python 3.12; el
`except TypeError` mantiene compatibilidad con 3.10 y 3.11, donde tendrás que
confiar más en el origen.

Y por eso mismo los pesos van en NPZ sin pickle: ver
[Lab 1](11.3-lab1-patron-de-ficheros.md#por-que-npz-y-no-pickle).

## Servir los CSV

El nodo descarga los datasets por HTTP. Para el laboratorio basta:

```bash
cd data && python -m http.server 9000
```

La URL debe ser **alcanzable desde el nodo**, no desde tu portátil. Si el nodo
está en otra máquina, `localhost:9000` no vale.

En un despliegue real cada proveedor publica su dataset como asset en Ocean y
pasas `documentId` + `serviceId` en vez de una URL suelta; el nodo resuelve el
DDO, desencripta la URL y aplica el control de acceso. La estructura del job es
la misma.
