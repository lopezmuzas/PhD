# 11.3 Lab 1 · El patrón de ficheros

**Objetivo:** ver el flujo de datos con tus propios ojos. Cambia **una** cosa
respecto al Lab 0: los pesos viajan por el disco, no por memoria.

Sigue sin haber Docker ni Ocean.

```bash
make lab1
```

---

## Que pasa

```
 ronda  muestras  accuracy media  delta global
------------------------------------------------
     1       200          0.9616           nan
     2       200          0.9530       0.83875
     3       200          0.9561       0.54930
     5       200          0.9530       0.32541
     8       200          0.9586       0.20031
```

La columna importante es **`delta global`**: la distancia L2 entre los pesos de
esta ronda y la anterior. Baja de forma monotona: el modelo esta convergiendo.
Si se estanca o crece, algo va mal.

Es la metrica que más te va a servir en el Lab 3, cuando cada ronda cueste
minutos y no puedas permitirte 40 iteraciones para ver si funciona.

---

## La estructura que crea

```
work/
  ronda_01/
    hospital_a/
      inputs/   global.npz          <- lo que el orquestador deposita
      outputs/  update.npz          <- lo que el contenedor produce
                metrics.json
    hospital_b/ ...
    hospital_c/ ...
  ronda_02/ ...
  modelo_final.npz
```

Cada carpeta `hospital_X/` es una **simulación de `/data`** dentro de un
contenedor C2D. Mismo contrato, mismos nombres de fichero.

## El contrato de ficheros

Ya es el definitivo. En el Lab 2 solo cambian las rutas.

| Fichero | Direccion | Contenido |
|---------|-----------|-----------|
| `inputs/global.npz` | orquestador -> nodo | pesos de la ronda. **Ausente en la ronda 0** |
| `outputs/update.npz` | nodo -> orquestador | pesos tras entrenar en local |
| `outputs/metrics.json` | nodo -> orquestador | `{"num_samples": N, "loss": ..., "accuracy": ...}` |

### Por que NPZ y no pickle

`np.save(..., dtype=object)` + `allow_pickle=True` es el patrón que verás en
casi todos los tutoriales de FL. **Es ejecución remota de código.**

El orquestador deserializa ficheros producidos por N proveedores que no
controla. Un `.npy` con pickle puede ejecutar código arbitrario en tu máquina al
cargarlo. `np.savez` con arrays nombrados no necesita pickle, y
`load_params_npz` pasa `allow_pickle=False` explicitamente.

Hay un test que lo garantiza: `test_npz_rechaza_pickle`.

### Por que `num_samples` es obligatorio

FedAvg pondera por número de muestras. Sin ese número solo puedes hacer la media
simple, que es el bug que el ejemplo 03 cuantifica.
