# 11.10 Cómo está montado (código, doc y CI)

> **Qué responde:** ¿por qué el código no está pegado en el Markdown, y cómo se
> mantiene sincronizado con la documentación?

## La decisión de fondo: el código NO se pega en el Markdown

Un bloque de código dentro de un `.md` no se ejecuta, no se testea y no se
entera de que el código real ha cambiado. Es una copia que empieza a mentir el
día que alguien refactoriza.

La regla de esta sección:

> El código vive en `labs/`, **fuera** de `docs/`. Las páginas lo **incluyen**
> con `pymdownx.snippets`. Una sola fuente de verdad.

Consecuencia práctica: si alguien rompe `fedavg()`, `make test` falla en CI y la
documentación **no puede** seguir mostrando la versión buena, porque no tiene
copia propia.

**Por qué `labs/` fuera de `docs/`:** todo lo que hay dentro de `docs_dir` se
copia tal cual al sitio publicado. No quieres 2.000 líneas de Python, un
`Dockerfile` y una carpeta de tests servidos como ficheros estáticos. Snippets
lee de donde le digas.

## `mkdocs.yml`

### Extensiones necesarias

```yaml
markdown_extensions:
  - admonition
  - attr_list
  - md_in_html
  - tables
  - toc:
      permalink: true
  - pymdownx.details
  - pymdownx.superfences
  - pymdownx.tabbed:
      alternate_style: true
  - pymdownx.highlight:
      anchor_linenums: true
      line_spans: __span
  - pymdownx.inlinehilite
  - pymdownx.snippets:              # ← LA CLAVE
      base_path:
        - .                         # raíz del proyecto, para leer labs/
      check_paths: true             # un include roto FALLA el build
```

`check_paths: true` es lo que convierte esto en una red de seguridad: si
renombras `aggregation.py`, el build peta en vez de publicar un hueco.

## Incluir código real en las páginas

### Un fichero entero

````markdown
```python title="src/fedlab/ports.py"
--8<-- "labs/federado-ocean-c2d/src/fedlab/ports.py"
```
````

### Solo un trozo (recomendado)

El código ya lleva marcadores. Por ejemplo en `domain/round.py`:

```python
# --8<-- [start:caso-de-uso]
def run_local_round(store, source, learner, cfg) -> RoundResult:
    ...
# --8<-- [end:caso-de-uso]
```

Y en la página:

````markdown
```python title="El caso de uso completo"
--8<-- "labs/federado-ocean-c2d/src/fedlab/domain/round.py:caso-de-uso"
```
````

Marcadores disponibles ahora mismo:

| Marcador | Fichero | Qué muestra |
|---|---|---|
| `puertos` | `src/fedlab/ports.py` | Los tres `Protocol` |
| `caso-de-uso` | `src/fedlab/domain/round.py` | `run_local_round()` |
| `fedavg` | `src/fedlab/domain/aggregation.py` | La agregación ponderada |
| `composition-root` | `src/fedlab/entrypoints/client_main.py` | `build_store()` |

**Usa siempre marcadores, nunca rangos de líneas** (`file.py:10:25`). Los números
de línea se desincronizan en cuanto alguien añade un import; los marcadores
sobreviven a cualquier refactor.

## CI: que la doc no pueda mentir

`.github/workflows/docs.yml`:

```yaml
name: docs
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      # 1. el código que la doc muestra, funciona
      - run: pip install -r labs/federado-ocean-c2d/requirements-dev.txt
      - run: cd labs/federado-ocean-c2d && make test
      - run: cd labs/federado-ocean-c2d && ruff check src tests examples scripts

      # 2. la doc compila, sin enlaces ni includes rotos
      - run: pip install mkdocs-material
      - run: mkdocs build --strict
```

Los tres comandos juntos son la garantía entera:

- `make test` — el código hace lo que dice.
- `ruff check` — y está limpio.
- `mkdocs build --strict` — los enlaces existen y los `--8<--` resuelven.

## Descarga del laboratorio

Si quieres ofrecer el `.tar.gz` desde la página índice, ponlo en `docs/assets/`
y enlázalo:

```markdown
[Descargar el laboratorio :material-download:](../assets/federado-ocean-c2d.tar.gz){ .md-button }
```

Mejor aún: publica `labs/federado-ocean-c2d/` como repositorio propio y enlaza a
GitHub. Un tarball en el sitio se queda viejo en cuanto tocas el código.

---

## Alternativa: mantener el repo separado

Si prefieres que el laboratorio siga siendo un repositorio autónomo y
compartible:

```bash
git submodule add https://github.com/tu-usuario/federado-ocean-c2d labs/federado-ocean-c2d
```

| | Copiar (por defecto) | Submódulo |
|---|---|---|
| Una sola fuente de verdad | sí (el código) | sí (todo) |
| Editar la doc desde el libro | sí | no, se edita en el repo |
| El repo se puede compartir solo | pierde su `docs/` | sí |
| Complejidad | ninguna | git submodules |

Para un libro personal, copiar. Para algo que vayas a publicar como proyecto,
submódulo.
