# 11.2 Lab 0 · Federado puro

**Objetivo:** entender FedAvg. Sin Docker, sin Ocean, sin red, sin ficheros.

```bash
make lab0
```

Si algo falla aquí, es tu lógica federada. Más adelante ya no podrás decir eso.

---

## Ejemplo 01 - Dos parámetros que puedes leer

```bash
python examples/ex01_linear.py
```

Tres nodos, la recta `y = 3x + 2`, y un detalle importante: cada nodo ve un
**tramo disjunto del eje X** (`[-6,-2]`, `[-2,2]`, `[2,6]`). Ninguno puede
estimar bien la pendiente en solitario. Juntos, si.

```
Verdad oculta: w=3.0  b=2.0
 ronda         w         b   mse medio
     1    2.4715    0.4186      1.5575
     5    3.0006    1.3723      0.3215
    10    3.0006    1.7918      0.2482
    40    3.0004    1.9770      0.2406
```

El modelo tiene **dos números**. No hay graficas ni TensorBoard: miras la
columna y ves la convergencia. Ese es todo el objetivo.

Cosas que merece la pena probar:
- Cambia `x_range` para que los tres nodos vean el mismo tramo. Converge más rápido.
- Sube `epochs` a 500 y baja `rounds` a 3. Mismo presupuesto de gradientes, peor
  resultado: es **client drift**, y lo mediras en el ejemplo 02.

## Ejemplo 02 - Por que el federado es difícil

```bash
python examples/ex02_noniid.py
```

Una sola perilla: `alpha`, del reparto Dirichlet. Es el método estándar en la
literatura para simular heterogeneidad.

```
alpha = 100  -> practicamente IID
alpha = 1.0  -> desbalanceo realista
alpha = 0.1  -> patologico (un nodo casi solo ve una clase)
```

Medimos dos cosas, y ahí está la sorpresa:

| alpha | % clase 1 por nodo | accuracy | divergencia |
|-------|--------------------|----------|-------------|
| 100.0 | 0.48 0.48 0.51 0.50 | 0.7333 | 0.309 |
| 1.0 | 0.22 0.45 0.78 0.53 | 0.7300 | 1.755 |
| 0.3 | 0.44 1.00 0.94 0.23 | 0.7367 | 2.696 |
| 0.1 | *(partición degenerada)* | -- | -- |

**La accuracy no se mueve. La divergencia se multiplica por 9.**

### Por que

La regresión logística es **convexa**: tiene un único mínimo global. Promediar
soluciones locales sigue cayendo cerca de el aunque los nodos vean datos muy
distintos. FedAvg es sorprendentemente robusto en modelos convexos, y eso es un
resultado real, no un artefacto del ejemplo.

Una red neuronal profunda no tiene esa garantía:
- es no-convexa (multiples mínimos, y la media de dos mínimos puede estar en una
  zona pesima), y
- tiene **simetria de permutacion**: dos redes con pesos completamente distintos
  pueden calcular la misma funcion. Promediarlas destroza ambas.

**La leccion:** si tu prueba de concepto federada usa un modelo lineal y
funciona, no has probado nada sobre la red profunda que quieres desplegar. La
**divergencia** si es una senal que se traslada: mide la deriva antes de que te
explote en produccion.

### El nodo vacío

Con `alpha=0.1` la partición falla a proposito:

```
ValueError: alpha=0.1 dejo un nodo sin datos. Sube alpha o baja n_nodes.
```

Un nodo sin datos rompe FedAvg de forma silenciosa (division por cero o peso
cero). Es mucho mejor fallar aquí, con un mensaje que dice que hacer, que
descubrirlo en la ronda 3 de un job C2D de pago.

## Ejemplo 03 - La tabla que justifica el proyecto

```bash
python examples/ex03_hospitals.py
```

Tres hospitales de tamanos **muy** distintos (110/60/30), repartidos por edad
para que el sesgo sea sistematico y no aleatorio: un hospital geriatrico y uno
pediatrico no ven la misma poblacion.

```
================================================================
escenario                                       accuracy
================================================================
CENTRALIZADO (techo, ilegal en la practica)       0.9217
FEDERADO - FedAvg ponderado                       0.9217
FEDERADO - media simple (BUG)                     0.9167
----------------------------------------------------------------
SOLO LOCAL - Hospital A (n=110)                   0.9113
SOLO LOCAL - Hospital B (n=60)                    0.8613
SOLO LOCAL - Hospital C (n=30)                    0.6470
================================================================
```

Tres lecturas:

1. **El hospital pequeño pasa de 0.647 a 0.922.** +27.5 puntos sin ceder un solo
   dato. Ese es el argumento comercial entero.
2. **El federado alcanza el techo centralizado.** No siempre pasa, pero cuando
   pasa, la conversacion sobre compartir datos se acaba.
3. **La media simple cuesta 0.5 puntos.** Con nodos más desbalanceados el hueco
   crece. Por eso existe `test_fedavg_pondera_por_muestras`.

El test es independiente (`n=3000`, semilla distinta) y **nadie lo ha visto
jamas**: ni los hospitales ni el orquestador entrenan sobre el.

### El detalle honesto del presupuesto

Los tres escenarios usan **el mismo número total de pasos de gradiente**
(`ROUNDS * epochs`). Sin eso, la comparacion no vale nada: darle 25x más
iteraciones al federado y declararlo ganador sería trampa.

## Cómo está montado

`entrypoints/simulate.py`, entero:

```python
for r in range(rounds):
    updates = []
    for X, y in partitions:
        store = InMemoryStore(initial=global_params)
        result = run_local_round(store, ArraySource(X, y), learner_factory(), cfg)
        updates.append((result.params, result.num_samples))
    global_params = fedavg(updates)
```

`learner_factory()` crea un modelo **nuevo por nodo y por ronda**. Es
deliberado: compartir una instancia de learner entre clientes es el bug
silencioso más comun al simular FL en un solo proceso, porque el estado se
filtra entre nodos y los resultados salen demasiado buenos.

Y fijate en lo que **no** hay: ni `os`, ni ficheros, ni red. El mismo
`run_local_round` y el mismo `fedavg` que usaran los labs 2 y 3.
