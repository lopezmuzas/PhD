# 11.7 Problemas típicos del laboratorio

Por orden de frecuencia real, no de gravedad.

---

## 1. El job muere en estado 11 o 22 y el log no dice nada

**Arquitectura de la imagen.** Construiste en Apple Silicon (o ARM) y el nodo es
`amd64`. ocean-node valida el manifiesto (`checkManifestPlatform`) y rechaza sin
un mensaje util.

```bash
docker buildx build --platform linux/amd64 -t tu-usuario/fedlab:v1 -f docker/Dockerfile .
docker push tu-usuario/fedlab:v1

# comprobar
docker manifest inspect tu-usuario/fedlab:v1 | grep architecture
```

Segunda causa: **la imagen no esta publicada**. El nodo hace `pull`; una imagen
que solo existe en tu portátil no existe para el.

---

## 2. Estado 31 - Data provisioning FAILED

El nodo no pudo descargar el dataset.

- La URL debe ser alcanzable **desde el nodo**, no desde tu portátil.
  `localhost:9000` casi nunca vale.
- Prueba desde la propia máquina del nodo: `curl -I <url>`.
- Redirecciones, TLS autofirmado o autenticación también fallan aquí.

---

## 3. Estado 32 - Algorithm provisioning FAILED

Fallo al preparar el algoritmo: `image`/`tag`/`checksum` mal, registro privado
sin credenciales (`encryptedDockerRegistryAuth`), o el digest no corresponde a
ese tag.

```bash
docker pull tu-usuario/fedlab@sha256:abc123...   # si falla aquí, fallará allí
```

---

## 4. Estado 41 - Algorithm FAILED

Tu código reventó. **Descarga el log:**

```python
open("algo.log","wb").write(client.result(job_id, index=1))
```

Causas por frecuencia:

| Sintoma en el log | Causa |
|-------------------|-------|
| `No hay dataset en /data/inputs` (código 2) | el nombre del fichero descargado no acaba en `.csv`/`.npz`/`.txt`. Fija `FL_DATA_FILE` |
| `ValueError: Se esperaba w(6,), llego w(2,)` | `FL_FEATURES` no coincide con las columnas del CSV |
| `contiene NaN o celdas no numericas` | el CSV tiene texto, celdas vacias o separador distinto |
| Log **vacío** | falta `PYTHONUNBUFFERED=1` en el Dockerfile |
| `ConnectionError` / timeout | tu código intenta salir a la red. **No hay red.** Reproducelo con `docker run --network none` |

---

## 5. HTTP 400 "Invalid signature"

Ver [contrato, sección firmas](11.6-contrato-c2d.md#firma-de-peticiones).

- El mensaje es `address + nonce + comando`, **concatenados sin separadores**.
- El nonce debe ser **estrictamente mayor** que el guardado. Si reutilizas uno,
  falla. Usa milisegundos desde epoch.
- El **comando forma parte del mensaje**: una firma de `freeStartCompute` no
  sirve para `getComputeResult`.
- La direccion debe ser la checksummed de `eth_account`, no minusculas.

```bash
pytest tests/test_ocean_signature.py -q     # verifica el esquema aislado
```

---

## 6. El bucle de espera no termina nunca

Comparabas con `status == 7`. **Es `70`.** El `7` no existe en el enum, así que
el `while` gira para siempre. Usa `client.wait()`, que tiene timeout duro y
detecta los estados de fallo.

---

## 7. El modelo no mejora entre rondas

El fallo más caro, porque **todo parece funcionar**: los jobs terminan en 70, la
perdida baja dentro de cada job, y aun así no hay federación.

Diagnostico, en orden:

**a) Los pesos no llegan al contenedor.** Cada ronda entrena desde cero.

```bash
pytest tests/test_c2d_contract.py::test_entrypoint_continua_desde_los_pesos_recibidos
```

Comprueba que `algoCustomData` lleva `params` en las rondas > 0.

**b) `delta global` no baja.** Ejecuta el Lab 1 y mira la columna: debe decrecer
monotonamente. Si no, el problema es de hiperparametros, no de infraestructura.

**c) Estas usando media simple en vez de FedAvg ponderado.**

```bash
pytest tests/test_aggregation.py::test_fedavg_pondera_por_muestras
```

**d) Demasiadas epocas locales por ronda.** Es *client drift*: cada nodo se va
demasiado lejos antes de promediar. Baja `epochs`, sube `rounds`. El
[ejemplo 02](11.2-lab0-federado-puro.md#ejemplo-02-por-que-el-federado-es-dificil)
lo mide.

---

## 8. `ValueError: El modelo ocupa N bytes en JSON`

Tu modelo no cabe en `algoCustomData`. Opciones:

1. Modelo más pequeño (para aprender, siempre es la respuesta correcta).
2. Publicar los pesos como asset cada ronda y pasarlos en `datasets`.
3. Usar persistent storage del nodo (`outputBucketId`), si esta configurado.

El limite de `MAX_JSON_BYTES` en `serialization.py` es **conservador y elegido
por nosotros**, no un limite documentado de Ocean. Ajustalo si tu nodo acepta
más, pero midelo antes.

---

## 9. `FileNotFoundError: El job no produjo update.npz/metrics.json`

El job termino en 70 pero el tar viene vacío o con otra cosa. Casi siempre:
escribiste fuera de `/data/outputs`, o el proceso murio después de entrenar y
antes de guardar. Mira el log (`index=1`) y la lista de ficheros que el error ya
te imprime.

---

## Checklist de bisecion

Cuando algo falle y no sepas por donde empezar, baja escalones hasta que algo
pase:

```bash
make test    # 1. dominio y contrato, sin Docker    < 2 s
make lab0    # 2. logica federada                    ~30 s
make lab1    # 3. patrón de ficheros                 ~5 s
make lab2    # 4. contrato contra la imagen real     ~1 min
             # 5. un solo job C2D (Lab 3, paso 2)
             # 6. bucle federado completo
```

El primer escalon que falle acota el problema. Esa es la razón de ser de los
cuatro labs.
