## Rutas dentro del contenedor

El nodo crea un volumen y lo monta en `/data`:

```
/data/
  inputs/            assets descargados + algoCustomData.json
  ddos/              DDOs de los assets (OJO: plural)
  outputs/           lo único que sale del contenedor
  logs/              stdout/stderr recogidos por el nodo
  transformations/   el algoritmo, si se envió como código suelto
```

> Muchas guias (y la versión anterior de este documento) dicen `/inputs` y
> `/outputs` en la raiz, o `/data/ddo` en singular. **Es incorrecto.**

Confirmado en `compute_engine_docker.ts`:

```javascript
baseFolder + '/data/inputs',
baseFolder + '/data/transformations',
baseFolder + '/data/ddos',
baseFolder + '/data/outputs',
baseFolder + '/data/logs',
```

### `/data/inputs`

**`algoCustomData.json` siempre existe**, aunque el job no envie nada:

```javascript
appendFileSync(configLogPath, "Writing algocustom data to '/data/inputs/algoCustomData.json'\n")
writeFileSync(customdataPath, JSON.stringify(job.algorithm.algocustomdata ?? {}))
```

Por eso la ronda 0 no necesita caso especial: el fichero esta, contiene `{}`, y
`load_global()` devuelve `None`.

**Los datasets se guardan con su nombre de fichero ORIGINAL:**

```javascript
const fullPath = jobFolderPath + '/data/inputs/' + fileInfo[0].name
```

El algoritmo **no conoce ese nombre de antemano**. Por eso
`find_dataset_file()` busca por extensión y descarta `algoCustomData.json`.
Alternativa: fijarlo con la variable de entorno `FL_DATA_FILE`.

### `/data/outputs`

El nodo empaqueta esta carpeta entera en un tar y la sirve como resultado
(`index=0`). Lo que no este aquí, se pierde al destruirse el contenedor.

## Entorno de ejecución

| Restriccion | Valor | Implicacion |
|-------------|-------|-------------|
| Red | `NetworkMode: 'none'` salvo `env.enableNetwork` | **Sin sockets.** Nada de Flower gRPC, ni pip install, ni telemetria |
| Usuario | `C2D_CONTAINER_UID:GID` (no-root) | No escribas fuera de `/data/outputs` |
| Capacidades | `CapDrop: ALL` | Sin privilegios de ningún tipo |
| Privilegios | `no-new-privileges` | Sin escalada |
| Procesos | `PidsLimit: 512` | Cuidado con multiprocessing agresivo |
| Memoria / CPU | según `resources` del job | `MemorySwap = Memory` (sin swap) |
| Arquitectura | validada (`checkManifestPlatform`) | `amd64` obligatorio en nodos `amd64` |

```javascript
if (!env.enableNetwork) {
  hostConfig.NetworkMode = 'none'
}
```

**Esta línea es el motivo de todo el diseño de este laboratorio.**

## Firma de peticiones

Lo más fácil de equivocar, y produce el error más opaco (HTTP 400, "Invalid
signature", sin más detalle).

De `nonceHandler.ts`:

```javascript
const message = String(String(consumer) + String(nonce) + String(command))
const consumerMessage = ethers.solidityPackedKeccak256(
  ['bytes'], [ethers.hexlify(ethers.toUtf8Bytes(message))]
)
const messageHashBytes = ethers.toBeArray(consumerMessage)
// acepta verifyMessage sobre consumerMessage O sobre messageHashBytes
```

Traducido a Python:

```python
from eth_account import Account
from eth_account.messages import encode_defunct
from eth_utils import keccak

message   = f"{address}{nonce}{command}"      # concatenados, SIN separadores
digest    = keccak(text=message)              # solidityPackedKeccak256(['bytes'],[x]) == keccak(x)
signature = account.sign_message(encode_defunct(digest)).signature.hex()
```

Dos trampas:

1. **El nonce debe ser estrictamente mayor** que el almacenado
   (`if (nonce <= existingNonce) return invalid`), y se actualiza en cada
   petición aceptada. Por eso `_nonce()` usa milisegundos desde epoch: monotono
   y siempre por delante.
2. **El comando forma parte del mensaje.** Firmar `freeStartCompute` y llamar a
   `getComputeResult` con esa firma no vale.

Nombres exactos (`src/utils/constants.ts`):

```
FREE_COMPUTE_START: 'freeStartCompute'
COMPUTE_GET_STATUS: 'getComputeStatus'
COMPUTE_GET_RESULT: 'getComputeResult'
```

> `docs/API.md` describe el mensaje de firma de forma inconsistente para varios
> comandos. **Fiate del código.**

## Petición de job

```json
{
  "command": "freeStartCompute",
  "consumerAddress": "0x...",
  "nonce": "1754839200000",
  "signature": "0x...",
  "environment": "0x7d18...-0xbeaf...",
  "datasets": [
    {"fileObject": {"type": "url", "url": "https://.../data.csv", "method": "GET"}}
  ],
  "algorithm": {
    "meta": {
      "container": {
        "image": "tu-usuario/fedlab",
        "tag": "v1",
        "checksum": "sha256:abc123...",
        "entrypoint": "python -m fedlab.entrypoints.client_main"
      }
    },
    "algocustomdata": {"round": 3, "params": [[...]], "config": {"epochs": 40}},
    "envs": {"FL_MODEL": "logistic", "FL_FEATURES": "6"}
  },
  "resources": [{"id": "cpu", "amount": 1}]
}
```

Notas:

- **`datasets` acepta un `fileObject` con URL directa**, sin publicar un asset.
  Para el laboratorio es oro: te saltas todo el ciclo de publicación.
- **`envs`** llega al contenedor como variables de entorno. Es como el
  orquestador configura el modelo sin reconstruir la imagen.
- **`entrypoint`** se separa por espacios. Si contiene `$ALGO`, el nodo lo
  sustituye por `data/transformations/algorithm` (ruta **relativa**).
- **`checksum`** produce `image@sha256:...`; sin el, `image:tag`; sin tag,
  `image:latest`.
- También puedes enviar `meta.container.dockerfile` y que el nodo **construya**
  la imagen (estados 12/13). Más lento y más superficie de fallo: para
  laboratorio, mejor una imagen ya publicada.

## Contrato de nuestro algoritmo

Lo que este laboratorio añade encima del contrato de Ocean:

**Entrada**
- `/data/inputs/<cualquiera>.csv` - cabecera, última columna = etiqueta
- `/data/inputs/algoCustomData.json`:
  ```json
  {"round": 3, "params": [[0.1, 0.2], [0.5]], "config": {"epochs": 40, "lr": 0.4}}
  ```
- Variables de entorno: `FL_MODEL`, `FL_FEATURES`, `FL_DATA_FILE`,
  `FL_INPUT_DIR`, `FL_OUTPUT_DIR`

**Salida**
- `/data/outputs/update.npz` - arrays `p0`, `p1`, ... **el orden es el contrato**
- `/data/outputs/metrics.json` - `{"num_samples": N, "loss": ..., "accuracy": ...}`

**Códigos de salida**
- `0` correcto | `1` excepcion (traceback en el log) | `2` no se encontro dataset
