# 5.5 Preentrenados

> **Reutilizar en lugar de reinventar:** En el Deep Learning moderno, prácticamente nadie entrena una red neuronal desde cero salvo por motivos de investigación fundamental. Se parte de un **modelo de fundación preentrenado** (Llama, ResNet, CLIP, Whisper) que ya acumula millones de dólares en cómputo y se adapta mediante *fine-tuning* o *prompt engineering*.

---

## 🧭 La intuición antes que la fórmula

Imaginas que quieres enseñar a alguien a analizar contratos médicos en español. Tienes dos caminos:

1. Enseñar a un bebé desde cero a hablar, leer, entender la biología y luego el derecho médico.
2. Contratar a un médico hispanohablante y darle un curso de 2 horas sobre las particularidades de tus contratos.

El modelo preentrenado **es el médico**: ya sabe lenguaje, sintaxis y estructura del mundo. El *transfer learning* es la formación de 2 horas.

## 🏗️ Los Niveles de Adaptación de un Modelo Preentrenado

```none
  [ Modelo Preentrenado Pesado (Llama 3, ViT) ]
                    │
                    ├── 1. Zero-Shot / Few-Shot ──▶ Solo Prompts / Contexto (Inferencia pura)
                    ├── 2. Linear Probe / Feature Extractor ──▶ Congelar tronco + Clasificador lineal (→ 3.7)
                    ├── 3. Adaptación Eficiente (PEFT / LoRA) ──▶ Congelar 99% + Adaptadores LoRA (→ 3.7)
                    └── 4. Full Fine-Tuning ────────────────────▶ Actualizar todos los pesos (Muy caro)
```

| Nivel | Pesos Modificados | Requisitos de Cómputo | Cuándo Usarlo |
|---|---|---|---|
| **Zero-Shot / In-Context** | 0 % | Solo Inferencia | Prototipado rápido, tareas de propósito general. |
| **LoRA / QLoRA (PEFT)** | $< 1 \%$ | 1 GPU de consumo | Adaptar LLMs o modelos de visión a dominios específicos. |
| **Full Fine-Tuning** | 100 % | Clúster multi-GPU | Cambiar radicalmente el formato o lenguaje objetivo del modelo. |

## 🔒 Soberanía y Despliegue en Data Spaces

El uso de modelos preentrenados plantea una decisión crítica entre dos paradigmas de despliegue:

1. **APIs Externas Propietarias (OpenAI, Anthropic, Google)**:
   - *Ventajas*: Máximo rendimiento, cero infraestructura propia.
   - *Inconvenientes*: **Violación potencial de soberanía de datos**, dependencia de terceros, costes por token impredecibles.
2. **Modelos Open-Weights On-Premise (Llama 3, Qwen 2.5, Mistral)**:
   - *Ventajas*: **Soberanía total de datos**, despliegue offline, cero fugas de información sensible.
   - *Inconvenientes*: Requiere GPUs locales y gestión de infraestructura.

> **Regla para Data Spaces (ITV, Sanidad, Industria):** Salvo excepciones en prototipado inicial, la arquitectura debe basarse en **modelos de código abierto / pesos abiertos (*open-weights*) ejecutados en infraestructura soberana local o federada**.

## 🧪 Práctica recomendada

- [ ] Descargar un modelo preentrenado pequeño (ej. `Qwen/Qwen2.5-1.5B-Instruct` o `google/vit-base-patch16-224`) desde Hugging Face.
- [ ] Medir la latencia de inferencia y uso de VRAM corriendo en local vs. usando una llamada de API.
- [ ] Aplicar **LoRA** con PEFT sobre el modelo para adaptarlo a una tarea tabular/texto propia.
