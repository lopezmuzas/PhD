# 4.8 El pipeline real: cómo se encadenan

> **La intuición fundamental:** Ningún sistema de IA moderno de vanguardia usa un
> único paradigma aislado. Los sistemas reales **componen y encadenan múltiples
> fuentes de señal**, y cada fase corrige los fallos estructurales de la anterior.

---

## ⛓️ El pipeline estándar de un modelo de fundación

```none
  [ Datos crudos (billones de tokens) ] ──▶ 1. Auto-supervisado (§4.3) ──▶ Modelo Base (capacidad / conocimiento)
                                                    │
  [ Demostraciones de calidad ] ──────────▶ 2. SFT / Imitación (§4.4)  ──▶ Modelo Instruido (formato / obediencia)
                                                    │
  [ Comparaciones humano/IA ] ────────────▶ 3. Preferencias / DPO (§4.5) ──▶ Modelo Alineado (tono / seguridad)
                                                    │
  [ Tests / verificadores ] ──────────────▶ 4. RL / RLVR (§4.6)        ──▶ Modelo Razonador (deliberación)
                                                    │
  [ Modelo maestro grande ] ──────────────▶ 5. Destilación (§4.7)      ──▶ Modelo Desplegable (rápido / eficiente)
```

---

## 📊 Comparativa del pipeline en cada fase

| Fase | Paradigma | Fuente de señal | Tamaño del dataset | Función en el sistema |
|---|---|---|---|---|
| **1. Preentrenamiento** | Auto-supervisado (§4.3) | El propio dato (siguiente token / máscara) | $10^{12}-10^{13}$ tokens | Inyectar conocimiento del mundo, gramática y razonamiento latente |
| **2. SFT** | Imitación (§4.4) | Demostraciones de alta calidad $(x,y)$ | $10^4-10^5$ ejemplos | Adaptar la interfaz a responder preguntas y seguir instrucciones |
| **3. Alineamiento** | Preferencias / DPO (§4.5) | Pares de preferencia $y_w \succ y_l$ | $10^4-10^5$ pares | Refinar tono, reducir toxicidad, evitar evasivas |
| **4. Razonamiento** | RL / RLVR (§4.6) | Recompensas verificables ($R \in \{0,1\}$) | $10^5-10^6$ problemas | Descubrir estrategias de razonamiento autónomas |
| **5. Despliegue** | Destilación (§4.7) | Logits / salidas del modelo de la fase 4 | Variable | Producir modelos compactos aptos para ejecución local |

---

## 💡 Qué restricciones de orden son reales

Hay tres dependencias duras. Conviene entenderlas como **restricciones**, no como un
guion fijo:

1. **No hay SFT sin preentrenamiento.** Sin las representaciones latentes de la fase
   auto-supervisada, el modelo memorizaría las demostraciones sin generalizar.
2. **No hay preferencias sin SFT.** Un modelo base genera texto continuo sin estructura
   de diálogo; no puedes pedirle que elija entre dos "respuestas a una instrucción" si
   aún no sabe responder instrucciones.
3. **No hay RLVR sin una base razonablemente capaz.** Si la exploración del modelo
   inicial nunca acierta por azar ($R = 0$ siempre), el gradiente de política no recibe
   ninguna señal.

### ⚠️ Pero no es una línea recta: es un ciclo

La secuencia 1→2→3→4→5 es una **simplificación didáctica**. Los pipelines reales
iteran:

```none
      ┌──────────────────────────────────┐
      ▼                                  │
   SFT ──▶ RL ──▶ generar datos ──▶ re-curar ──┘   (varias vueltas)
```

Dos contraejemplos que conviene tener presentes, porque desmontan la lectura rígida:

- **DeepSeek-R1-Zero** aplicó **RLVR directamente sobre el modelo base**, sin SFT de
  razonamiento previo (→ §4.9). La restricción 3 se cumplía; la 2 se saltó por
  innecesaria en ese objetivo.
- **DeepSeek-R1** hizo un SFT semilla, luego RLVR masivo, y **después** volvió a SFT y
  preferencias para limpiar las trazas. Es decir: la fase 3 va *después* de la 4.

> **La formulación correcta:** el orden tiene **precondiciones**, no una secuencia
> única. Cada fase exige que ciertas capacidades ya existan; el resto es diseño.

## 🧠 Caso de estudio: el pipeline de un modelo de razonamiento

```none
1. Preentrenamiento auto-supervisado (§4.3) ──▶ Modelo base (conocimiento general)
2. SFT semilla / "arranque en frío" (§4.4)  ──▶ Corpus CoT pequeño, para estabilizar formato
3. RLVR masivo sobre recompensa (§4.6)      ──▶ Emergencia de razonamiento largo y auto-corrección
4. Re-curado por SFT / preferencias (§4.4/5)──▶ Trazas legibles, seguras y sin bucles
5. Destilación a modelos pequeños (§4.7)    ──▶ Modelos compactos con capacidad de razonamiento
```

> **Lección del pipeline:** el razonamiento es una **capacidad de tiempo de inferencia**
> que se *descubre* mediante RLVR (§4.6), se *pule* con SFT (§4.4) y se *empaqueta*
> mediante destilación (§4.7). Los pasos 3 y 4 pueden repetirse.

---

## ⚠️ El reparto de cómputo: una cifra que se mueve rápido

La regla clásica —"el preentrenamiento se lo lleva casi todo"— **está dejando de ser
cierta**, y conviene documentarla con fecha en vez de como ley:

| Referencia | Cómputo de post-entrenamiento |
|---|---|
| **DeepSeek-R1** (2025) | ≈ **5 %** del total: 147K horas H800 de RL frente a 2,8M de preentrenamiento del modelo base V3 |
| **DeepSeek-R1-Zero** | **3,75 %** del cómputo de preentrenamiento: 100K horas H800 |
| **o1 → o3** (OpenAI, 2025) | Aumento de **más de 10×** en cómputo de RL entre generaciones |
| **Cursor Composer 1.5** (sept. 2025) | El post-entrenamiento **superó** al preentrenamiento del modelo base |

```none
   2023  preentrenamiento ████████████████████  post ▏
   2025  preentrenamiento ████████████████      post █
   2026  preentrenamiento ██████████            post ██████████   ← inversión en la frontera
```

> **Lo que sí se mantiene:** cada fase posterior usa **órdenes de magnitud menos
> datos**, pero exige una **calidad de señal inmensamente mayor**. Esa relación no ha
> cambiado; la del cómputo sí.

```none
  Datos requeridos:   Preentrenamiento (10¹³) ──▶ RLVR (10⁶) ──▶ SFT/DPO (10⁴)
  Calidad exigida:    Preentrenamiento (media) ──▶ SFT (extrema) ──▶ Preferencias (muy alta)
```

**Nota de mantenimiento:** cifras verificadas en agosto de 2026. Es la sección de todo
el capítulo que envejece más deprisa; revísala antes de citarla.

### 📖 Para entender el pipeline entero

| [RLHF Book](https://rlhfbook.com) (Nathan Lambert) | 📖 | **El mejor recurso único de esta página.** Gratuito y en desarrollo. Cubre SFT, modelos de recompensa, RLHF, DPO y RLVR con la historia y los detalles de implementación. De uno de los autores que acuñó el término RLVR |
| [The Illustrated DeepSeek-R1](https://newsletter.languagemodels.co/p/the-illustrated-deepseek-r1) (Jay Alammar) | 📖🎨 | Diagrama a diagrama, el pipeline de R1 completo. El complemento visual perfecto al report técnico |
| [Alignment Handbook](https://github.com/huggingface/alignment-handbook) (Hugging Face) | 🛠️ | Recetas de código para ejecutar SFT y DPO sobre modelos abiertos. Lo que usarás en la práctica |
